# Lost & Found ICT

ระบบบริหารจัดการของหายและของที่พบภายในคณะ ICT มหาวิทยาลัยพะเยา

2. 68026394 นางสาวชนิกานต์ แก้ววงค์เขียว

## คำอธิบายเว็บ Lost & Found ICT

**Lost & Found ICT System** เป็นระบบบริหารจัดการของหายและของที่พบภายในคณะ ช่วยให้ผู้ใช้สามารถแจ้ง ค้นหา ติดตามสถานะ และขอรับทรัพย์สินคืนผ่านระบบออนไลน์ได้อย่างสะดวก พร้อมสนับสนุนการทำงานของเจ้าหน้าที่ในการตรวจสอบ จัดเก็บ และส่งคืนทรัพย์สินอย่างเป็นระบบ โปร่งใส และตรวจสอบได้

ข้อกำหนดและรายละเอียดของระบบทั้งหมด ดูได้ที่ → [requirements.md](./requirements.md)

### Tech Stack

## ฟีเจอร์หลัก

### สำหรับผู้ใช้งานทั่วไป
- สมัครสมาชิก เข้าสู่ระบบ และจัดการโปรไฟล์
- แจ้งของหาย / แจ้งพบของ แบบฟอร์ม 3 ขั้นตอน (ประเภทและรายละเอียด → สถานที่และเวลา → รูปภาพ)
- แสดงกระดานรายการสิ่งของ และค้นหา / คัดกรองตามหมวดหมู่ ช่วงวันที่ และสถานที่
- ดูรายละเอียดสิ่งของ รวมถึงหมวดหมู่ จุดจัดเก็บ และตำหนิที่ใช้ยืนยันสิทธิ์
- ยื่นคำร้องขอรับคืน พร้อมแนบหลักฐานและคำอธิบายการเป็นเจ้าของ
- ติดตามสถานะรายการที่แจ้ง และสถานะคำร้องของตนเอง
- แก้ไขหรือถอนโพสต์ของตนเองได้ในขณะที่สิ่งของยังไม่ถูกนำส่งเข้าจุดรับฝาก

### สำหรับเจ้าหน้าที่และผู้ดูแลระบบ
- แดชบอร์ดสรุปสถิติสิ่งของ จำนวนรายการตกค้าง และประวัติการส่งมอบล่าสุด
- ตรวจสอบรายการแจ้งพบสิ่งของและรายละเอียดโพสต์
- บันทึกรับฝากสิ่งของเข้าคลัง พร้อมระบุห้อง ชั้น และช่องจัดเก็บจริง
- ตรวจสอบคำร้องขอรับคืน และอนุมัติ / ขอข้อมูลเพิ่ม / ปฏิเสธ พร้อมบันทึกเหตุผล
- บันทึกการส่งมอบของคืนแก่เจ้าของ พร้อมภาพหลักฐาน
- ติดตามรายการตกค้างเกินกำหนด และบันทึกการจำหน่าย
- จัดการโปรไฟล์เจ้าหน้าที่

## วิธีการติดตั้งและรัน

### 1. Clone Repository

```bash
git clone https://github.com/tyfoon-art/Project-Fron-end.git
cd Project-Fron-end
```

### 2. ติดตั้ง Dependencies

ต้องใช้ Node.js 18 ขึ้นไป

```bash
npm install
```

### 3. ตั้งค่า Supabase

1. สมัครสมาชิกและเข้าสู่ระบบที่ https://supabase.com
2. สร้างโปรเจกต์ใหม่
3. รอระบบสร้างฐานข้อมูลให้เสร็จ
4. ไปที่ `Project Settings → API`
5. คัดลอกข้อมูล 2 ค่านี้
   - `Project URL`
   - `anon public` key
6. สร้างไฟล์ `.env` ไว้ที่ root ของโปรเจกต์

```env
VITE_SUPABASE_URL=your_supabase_url
VITE_SUPABASE_ANON_KEY=your_supabase_anon_key
```

> ไฟล์ `.env` มีข้อมูลสำคัญของโปรเจกต์ **ห้าม commit ขึ้น GitHub**
> ให้เพิ่ม `.env` และ `node_modules` ในไฟล์ `.gitignore` ก่อนใช้งานจริง

### 4. สร้างตารางฐานข้อมูล

เปิด `Supabase Dashboard → SQL Editor → New Query` แล้วสร้างตารางตามลำดับนี้

1. `category`
2. `claim`
3. `claim_activity_log`
4. `claim_proof`
5. `disposal`
6. `handover`
7. `item`
8. `item_history_log`
9. `item_media`
10. `item_secret`
11. `notification`
12. `report`
13. `storage_point`
14. `user_account`

บัญชีผู้ใช้ทุกประเภท (`user`, `staff`, `admin`) เก็บใน `user_account` ตารางเดียว แยกด้วยคอลัมน์ `role`
ส่วนตำหนิลับของของเก็บแยกไว้ใน `item_secret` และต้องอ่านผ่าน RPC `get_staff_defect_note` เท่านั้น

รายละเอียดคอลัมน์และความสัมพันธ์ของแต่ละตาราง ดูได้ที่หัวข้อ
[Data and Database Expectations](./requirements.md#7-data-and-database-expectations)

### 5. สร้าง Stored Procedure / RPC

ระบบเรียกใช้ฟังก์ชันฝั่งฐานข้อมูลผ่าน RPC ดังนี้ ต้องสร้างให้ครบก่อนเปิดใช้งาน

| RPC | หน้าที่ |
|-----|--------|
| `register_user` | สมัครสมาชิกใหม่ |
| `verify_login` | ตรวจสอบอีเมลและรหัสผ่าน |
| `update_user_profile` | อัปเดตข้อมูลโปรไฟล์ผู้ใช้ |
| `staff_upsert_profile` | เพิ่ม/แก้ไขโปรไฟล์เจ้าหน้าที่และผู้ดูแลระบบ |
| `staff_update_avatar` | อัปเดตรูปโปรไฟล์ของเจ้าหน้าที่ |
| `create_report` | สร้างรายการแจ้งของหาย / แจ้งพบของ พร้อมบันทึกตำหนิลับลง `item_secret` |
| `staff_create_item` | เจ้าหน้าที่สร้างรายการสิ่งของที่รับเข้ามาใหม่ |
| `delete_report` | ยกเลิกโพสต์ของผู้ใช้เอง |
| `get_staff_defect_note` | อ่านตำหนิลับจาก `item_secret` โดยตรวจสอบสิทธิ์ก่อน |
| `create_claim` | ยื่นคำร้องขอรับคืนพร้อมหลักฐาน |
| `staff_review_claim` | ตรวจสอบ อนุมัติ หรือปฏิเสธคำร้อง พร้อมบันทึกประวัติ |
| `staff_receive_item` | บันทึกรับฝากเข้าจุดรับฝากพร้อมตำแหน่งจัดเก็บจริง |
| `record_handover` | บันทึกการส่งมอบของคืนแก่เจ้าของ |
| `staff_dispose_item` | บันทึกการจำหน่ายสิ่งของตกค้างเกินกำหนด |
| `admin_upsert_storage_point` | เพิ่ม/แก้ไขจุดเก็บของ |
| `admin_delete_storage_point` | ปิดใช้งานหรือลบจุดเก็บของ |

### 6. ตั้งค่า Row Level Security

ต้องกำหนดสิทธิ์ในการอ่าน/เขียนแต่ละตารางให้สอดคล้องกับบทบาทของผู้ใช้ โดยเฉพาะตาราง
`user_account`, `claim` และ **`item_secret`** ที่มีข้อมูลส่วนบุคคล โดย `item_secret` ต้องปิดการอ่านตรงจาก client
และให้อ่านผ่าน RPC `get_staff_defect_note` เท่านั้น

### 7. รันโปรเจกต์

```bash
npm run dev
```

ระบบจะแสดง URL เช่น `http://localhost:5173` เปิดผ่านเว็บเบราว์เซอร์เพื่อใช้งาน

หลังแก้ไขไฟล์ใน `.env` ต้อง **รีสตาร์ท dev server** อีกครั้งจึงจะมีผล

## วิธีการใช้งาน

### ผู้ใช้งานทั่วไป

1. เปิด `http://localhost:5173/login.html` แล้วสมัครสมาชิกหรือเข้าสู่ระบบ
2. จะถูกพาไปยังหน้าหลัก `home.html` ซึ่งแสดงรายการสิ่งของล่าสุด
3. กด **แจ้งของหาย / พบของ** เพื่อเริ่มกรอกข้อมูล 3 ขั้นตอน
4. ค้นหาหรือคัดกรองสิ่งของจากเมนูค้นหา หรือเปิด `browse.html`
5. เมื่อพบสิ่งของของตน ให้เปิดหน้ารายละเอียดแล้วกด **ยื่นคำร้องขอรับคืน**
   - ระบบจะไม่ให้ยื่นคำร้องซ้ำถ้ามีคำร้องที่ยังรอการตรวจสอบอยู่แล้ว
   - ยื่นได้เฉพาะสิ่งของที่มีสถานะ `อยู่ที่จุดรับฝาก` เท่านั้น
6. ติดตามผลการพิจารณาได้ที่ `activity.html`

### เจ้าหน้าที่ / Admin

1. เข้าสู่ระบบด้วยบัญชีที่มี `role` เป็น `staff` ระบบจะพาไปยัง `staff-dashboard.html` โดยอัตโนมัติ
2. ตรวจสอบคิวคำร้องที่ `staff-verify-claims.html`
   - เปิดรายละเอียดเพื่อดูหลักฐานและตำหนิที่ใช้ยืนยันสิทธิ์
   - เลือก **อนุมัติ** / **ขอข้อมูลเพิ่ม** / **ปฏิเสธ** พร้อมระบุเหตุผล
   - ทุกการพิจารณาจะถูกบันทึกใน `claim_activity_log`
3. เมื่อผู้มารับของที่ได้รับอนุมัติแล้ว ให้บันทึกการส่งมอบที่ `staff-handover.html`
   - ต้องแนบภาพหลักฐานการรับของอย่างน้อย 1 ภาพ
4. รายการที่จัดเก็บเกินกำหนดจะอยู่ที่ `staff-overdue-list.html` และให้จำหน่ายได้ที่ `staff-dispose-item.html`

## สถาปัตยกรรม (สรุปสั้น)

### การไหลของข้อมูล

`หน้าเว็บ (browser)` → เรียก `supabase-js` โดยตรง → **PostgREST** สำหรับอ่าน/เขียนตาราง
และ **Stored Procedure / RPC** สำหรับตรรกะเชิงธุรกิจ → **PostgreSQL** · รูปภาพเก็บบน **Supabase Storage**

ไม่มี Node.js server แยกต่างหาก ตรรกะเชิงธุรกิจที่กระทบหลายตารางจึงอยู่ที่ฝั่งฐานข้อมูล
ผ่าน RPC 16 ตัว (ดูรายการในข้อ **5. สร้าง Stored Procedure / RPC**)

### การยืนยันตัวตน

- สมัครสมาชิกและเข้าสู่ระบบผ่าน RPC `register_user` / `verify_login` บนตาราง `user_account`
  ซึ่งเก็บทุกบทบาท (`user`, `staff`, `admin`) ในตารางเดียว แยกด้วยคอลัมน์ `role`
- ไม่มีการเขียนระบบ JWT หรือ hashing รหัสผ่านเองในฝั่ง JavaScript
- `supabase.auth` ถูกใช้เฉพาะจุดลืมรหัสผ่าน (`resetPasswordForEmail`) และการเช็ค session ในบางหน้า
  (`forgotpassword.js`, `profile.js`, `browse.js`) — ยังไม่มี OAuth หรือ Magic link
- หน้าของเจ้าหน้าที่และผู้ดูแลถูกคุ้มกันด้วย `requireStaff` ใน `src/js/staff-auth.js` ทุกหน้า

### การควบคุมสิทธิ์

- **ชั้นที่ 1 — Row Level Security** ที่ฐานข้อมูล เป็นขั้นตอนตั้งค่าที่ระบุไว้ในข้อ 6
  โดยเฉพาะตาราง `item_secret` ที่ต้องปิดการอ่านตรงจาก client
- **ชั้นที่ 2 — RPC** ที่ตรวจสอบสิทธิ์ในเงื่อนไข ได้แก่ `get_staff_defect_note`, `staff_review_claim`,
  `record_handover`, `staff_dispose_item`
- หมายเหตุ: โปรเจกต์ยังไม่มีไฟล์ `.sql` เก็บใน repo นโยบาย RLS จึงต้องตั้งค่าผ่าน Supabase SQL Editor
  และตรวจสอบด้วยตัวเอง

### ฐานข้อมูล

- **14 ตาราง** แยกตามขอบเขตงาน (ดูรายการในข้อ **4. สร้างตารางฐานข้อมูล**)
- **16 RPC** เป็นจุดที่ตรรกะเชิงธุรกิจทุกอย่างถูกรวมไว้
- **Soft delete** ด้วยคอลัมน์ `deleted_at` และ **สถานะสิ่งของ** (`item.status`) เป็นตัวกำหนดว่าหน้าไหนแสดงปุ่มอะไรให้ใคร
- ยังไม่มี View, Function นอกชุด RPC และ Trigger ในโค้ด เพราะยังไม่มีไฟล์ SQL เก็บไว้ในโปรเจกต์
