# Gap Analysis — Lost & Found ICT

## 1. คำอธิบาย GAP_ANALYSIS.md

**เอกสารนี้เทียบระบบปัจจุบันกับ requirements** — เปรียบเทียบสิ่งที่ [requirements.md](../requirements.md) กำหนด
กับสิ่งที่โค้ดใน `src/` ทำจริง ครอบคลุมทุกข้อ Functional Requirements (F-01–F-10)
และทุกข้อ Business Rules (BR-01–BR-09)

หลักการตรวจ:
- ยึดโค้ดจริงใน `src/js/*.js` และ `src/*.html` เป็นแหล่งเดียว — ไม่ใช้การเดาจากชื่อไฟล์
- ทุกหลักฐานอ้างอิง `file:line` กำกับไว้ในตาราง
- การ "compile ผ่าน" คือแค่ขั้นต้น ไม่ใช่ข้อสรุป — ดูวิธีที่ตรวจสอบทั้งหมดในหัวข้อ 6
- รายละเอียดโครงสร้างฐานข้อมูลและความขัดแย้งสคีมา อยู่ที่ [docs/deliverables/DATA_DICTIONARY.md](./deliverables/DATA_DICTIONARY.md)

อัปเดตล่าสุด: จากสถานะโค้ดปัจจุบัน

## 6. วิธีที่ตรวจสอบ (ไม่ใช่แค่ "compile ผ่าน")

การตรวจนี้ครอบคลุมลำดับชั้นต่อไปนี้ ไม่หยุดแค่ build ผ่าน:

1. **อ่านโค้ดจริงทั้งหมด** — เปิดทุกไฟล์ใน `src/js/*.js` (24 ไฟล์) และ `src/*.html` แล้ว
   ทุกข้อสรุปในหัวข้อ 3–4 มีหลักฐาน `file:line` กำกับ ไม่มีข้อใดที่ใช้การเดาจากชื่อไฟล์
2. **ตรวจความครบไฟล์ HTML ↔ JS** — ตรวจ `<script src>` ของทุกหน้า เทียบกับไฟล์ใน `src/js/`:
   ตรงกัน 23/24 หน้า · ยกเว้น `staff-dispose-process.html` ที่ชี้ `js/staff-dispose-process.js` ซึ่งไม่มีอยู่จริง
3. **ตรวจลิงก์ข้ามหน้า** — grep ทุก `href="*.html"` ใน `src/`:
   `staff-dispose-process.html` ไม่มีหน้าใดเข้าถึงได้ (orphan)
4. **สแกนการเรียกฐานข้อมูล** — รายการ `.from(...)` / `.rpc(...)` ทั้งหมดใน `src/js` ครบ 16 RPC และ
   ตรงกับตาราง RPC ใน DATA_DICTIONARY §5 · ไม่พบ `.insert()`/`.update()`/`.delete()` ที่เขียนตารางตรงจาก client
5. **Build** — `npm run build` (Vite) ผ่าน และ `dist/` มีผลลัพธ์จริง ·
   แต่ build ผ่าน = ยืนยัน **syntax + ลิงก์ import เท่านั้น** ไม่ยืนยันว่าระบบทำงานถูกต้อง
6. **ข้อจำกัดของการตรวจ** — ตรวจชั้นโค้ดฝั่ง client ได้ 100% แต่**ไม่ได้รันกับโปรเจกต์ Supabase จริง** (ไม่มี `.env`/credentials)
   จึงแยกหมวด "ต้องยืนยันกับ DB จริง" ไว้ในหัวข้อ 7 (รายละเอียดใน DATA_DICTIONARY §8)

### 7.4 ต้องยืนยันกับ DB จริง (เห็นจากโค้ดฝั่งเดียว ไม่มี SQL ต้นทาง)

โค้ดฝั่ง client ขัดกันเองหรือไม่มีหลักฐานยืนยัน รายละเอียดและหลักฐานรายข้ออยู่ที่ [DATA_DICTIONARY §8](./deliverables/DATA_DICTIONARY.md#8-ความขัดแย้งที่ต้องยืนยันกับฐานข้อมูลจริง):

1. `claim` มีคอลัมน์ `status` หรือ `claim_status` — `activity.js:151` อ่าน `claim_status` ไม่ตรงที่อื่น
2. `item_secret` เป็นปลายทางของ `p_secret_image` (รูปลับ) จริงหรือไม่
3. `storage_point` ใช้ `room`/`description` และมี `is_active` ไหม (โค้ดไม่พบ `is_active` ของตารางนี้)
4. `item` มี `category`, `category_key`, `category_id` ครบทั้งสามหรือไม่ (โค้ดส่ง/อ่านทั้งสาม)
5. `item_id`/`claim_id` เป็นชนิด `text` (เช่น `ITM-2026-0001`) ไม่ใช่ uuid
6. `item.disposed_at` มีจริงหรือไม่ (`staff-overdue-list.js:127` อ่านจริง)
7. `report.description`/`report.image_url` เป็นคอลัมน์จริงหรือ `p_description`/`p_image_url` ลง `item` แทน
8. `user_account.password` ถูก hash ใน RPC หรือเก็บข้อความตรง
